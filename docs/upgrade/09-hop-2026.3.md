## Found on the way

1. **Tags are objects (the app breaks without a fix).**
   - From 2026.3, a topic's tags, `top_tags` and the tag filter list are `{ id, name, slug }` objects, not names.
   - Through Prose, the feed failed with "String cannot represent value" and tagged topics disappeared.
   - **Fix in Prose**, branch `fix/tag-objects`: `Topic.tags`, `TopicDetailOutput.tags`, `SearchTopic.tags` and `TopicList.topTags` resolve to names for both shapes, and `TagFilter.id` stays the name.
   - 8 tests cover the change. Through Prose on 2026.3, the feed has no errors and tagged topics show their tags again.
   - On hold with the other Prose fixes until all hops are done.
   - Check #34 accepts tag objects, because Prose handles both shapes.
2. **Poll setting:** `poll_minimum_trust_level_to_create` is unchanged and still sent to the app. Watch it at Hops 5 and 6.
3. **Safety-net script bugs.** The first full run was invalid: 2 of 30 flows passed, because the staging backup was never restored.
   - The stop command (`bash -lc 'pkill -f unicorn; pkill -f sidekiq'`) matched its own shell and killed it, so sidekiq was never stopped. 2026.3 also runs pitchfork, which the command did not know. The open connections then blocked PostgreSQL's restart after the restore script upgraded it to 15.19.
   - The restore script waited a fixed 5 seconds, so the restore started while PostgreSQL was still shutting down.
   - Fixed:
     - The stop command is now `pkill -f "[u]nicorn|[p]itchfork"; pkill -f "[s]idekiq"`.
     - The restore waits until PostgreSQL answers, and stops unless the restore is `[SUCCESS]`.
     - `safety-net.sh full` skips Layer C when the restore fails.
   - The re-run is the one in the table above.
4. **Disk:** with Mahmoud's OK, old hop leftovers and developer caches were cleared (31 GB). About 33 GB is free.
