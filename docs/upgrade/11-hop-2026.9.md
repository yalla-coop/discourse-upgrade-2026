## Found on the way

1. **Post previews: the planned security re-check found a crash (plugin fix).**
   - From 2026.x, `PostItemExcerpt` builds `cooked` from the post the item points at (`excerpt_source_post`, with `ContentLocalization` translations). It also hides the text from viewers who can't see that post (`can_see_post_item_excerpt?`).
   - The plugin's redefinition ignored all three. On 2026.9 the **bookmarks list crashed for everyone** (`undefined method 'cooked' for an instance of Bookmark`), and the permission check relied only on `include_excerpt?`.
   - Fixed in `discourse-forward-trust` (`264cbd2`): keep all three when present, and change only the result (the full cooked HTML). It also works on older Discourse.
   - Two new Layer A tests: a visible bookmark shows full HTML, and a bookmark of a post that became private shows nothing. Both fail on the old plugin (with the crash) and pass with the fix.
2. **Post notifications run as a delayed job.**
   - The seed added the "replied" notification itself. The delayed post alert then ran later and replaced it with "posted", so check #30 found no reply notification.
   - Real users get "replied" as before: `PostAlerter.post_created` was called directly and gave `[:replied]`.
   - The seed now creates the reply with `skip_jobs: true` and adds the notification once.
3. **Production's PostgreSQL** (Untapped section 3.5 recommends 15) is checked in the production-style build with the real launcher, not here. The dev image runs PostgreSQL 18.
