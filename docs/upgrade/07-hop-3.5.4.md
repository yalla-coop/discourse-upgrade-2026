## Found on the way

1. **Lexicon would not load** (Untapped's top risk). It pinned `gem 'ffi', '1.17.1'`, but core 3.5.4 already loads ffi 1.17.2: `can't activate ffi-1.17.1, already activated ffi-1.17.2`. A real rebuild would stop and leave the site down.
   - Core bumps ffi again at 2026.3 (1.17.3) and 2026.6 (1.17.4).
   - Fix on Lexicon branch `upgrade-2026`: `gem 'ffi', Gem.loaded_specs['ffi']&.version&.to_s || '1.17.1'`, which uses the version core already loaded. On today's production this evaluates to 1.17.1, so nothing changes there.

2. **Prose login failed after the first login** with 403 "Can't verify CSRF token authenticity". It was found by Layer C (TC033) and reproduced by hand.
   - Cause: Prose fetched the CSRF token through one shared cookie jar for all users. Discourse 3.5 (Rails 8) no longer re-sends an unchanged session cookie, while the old version did, which hid the bug. Proven side by side with `curl`.
   - Fix in the app repo, branch `fix/login-csrf` (`d248c9c73b`): the handshake uses its own client without a cookie jar. A new Prose test fails before the fix and passes after.
   - Login loop through Prose:

     | | Discourse 3.5.4 | Today's production code |
     |---|---|---|
     | Old Prose | 0 / 6 | not run |
     | Fixed Prose | 6 / 6 | 6 / 6 |

   - With the fix, Layer C is 29 / 29 on today's production code and 29 / 29 on 3.5.4. **Deploy the Prose fix before the production upgrade.**
   - Separately, the shared jar can carry one user's cookies into another user's anonymous request (registration and honeypot calls still use it). Worth a follow-up in Prose.

3. **Test script fixes.**
   - The shared hop folder kept the 3.4.7 test logins, so the first Layer B run failed at login. `script/safety-net.sh` now re-seeds when the container changes.
   - `script/layer-c.sh` has a `FLOWS=` option to run single flows.

   - The AVD's 6 GB data partition is nearly full, about 360 MB free. Android crashed once ("Can't find service: package"), and a cold boot fixed it.
